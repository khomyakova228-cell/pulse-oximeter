## 1. Задание

Для проекта пульсоксиметра в KiCad требовалось:

1. перерисовать условные графические обозначения (УГО) компонентов по ГОСТ и собрать из них библиотеку;
2. заполнить рамки и основные надписи по ГОСТ;
3. описать важные цепи классами цепей (с цветовым обозначением);
4. завести в компонентах поле `Manufacturer_Part_Number` с реальным партномером;
5. подключить библиотеку к проекту как **git-сабмодуль**, все пути библиотек — **относительные**;
6. написать скрипт `bash` и его аналог `.bat` для Windows: проверка **ERC**, **DRC**, генерация
   **Gerber**-файлов, **BOM** (перечень элементов), **PDF**-версии схемы;
7. разместить проект в git-репозитории на персональной странице GitHub;
8. оформить отчёт — PDF-версию файла `README.md` (этот документ).

Проект выполнен в KiCad 10.0. Скрипты рассчитаны на `kicad-cli` из KiCad 9 и 10.

## 4. Библиотека УГО по ГОСТ

Штатные символы KiCad выполнены по ANSI/IEC и не соответствуют ЕСКД. Для микросхем, соединителя,
кнопки и общего провода нарисованы собственные УГО (рисунок 2). Символы описаны кодом
(`lib/kicad-gost-lib/tools/gen_gost_lib.py`), поэтому размеры, шаг выводов и шрифты задаются
в одном месте и одинаковы во всех символах.

![УГО библиотеки GOST_UGO](lib/kicad-gost-lib/docs/preview_symbols.png)

<p class="caption">Рисунок 2 — УГО библиотеки GOST_UGO</p>

<p class="caption tcap">Таблица 2 — Состав библиотеки</p>

| Символ | Поз. обозн. | Стандарт | Особенности |
|---|---|---|---|
| `OPA340P` | DA | ГОСТ 2.759, 2.743 | основное поле со знаком «▷∞», инвертирующий вход — указатель инверсии, питание отдельной группой |
| `KR590KN2` | DA | ГОСТ 2.743 | функция «SW», группы: управление D1–D4, входы, выходы, питание |
| `LM1117MP-ADJ` | DA | ГОСТ 2.743 | вход и ADJ слева, выход справа |
| `STM32F030C8Tx` | DD | ГОСТ 2.743 | функция «MCU», выводы сгруппированы по портам, питание отдельной группой |
| `FT232RL` | DD | ГОСТ 2.743 | функция «USB/UART», активные низким уровнем выводы — кружком |
| `Conn_1x02…1x06` | X | ГОСТ 2.755 | таблица «Конт. / Цепь», наименования цепей — поля экземпляра `Цепь1…ЦепьN` |
| `SW_Push_NO` | SB | ГОСТ 2.755, 2.721 | замыкающий контакт, нажимной привод, механическая связь |
| `GND` | — | ГОСТ 2.721 | «заземление, общее обозначение» |

Общие правила: основное и дополнительные поля ИМС, группы выводов разделены линией и пустым шагом,
корпус без заливки, толщина линий УГО равна толщине линий связи, шаг выводов 2,54 мм. В каждом
символе заполнены `Footprint`, `Datasheet`, `Manufacturer`, `Manufacturer_Part_Number`.

## 6. Классы цепей

Классы заданы в *Файл → Параметры схемы → Проект → Классы цепей* и хранятся в
`pulse_oximeter.kicad_pro`. Цепи назначаются классам по шаблонам имён, поэтому классы
применяются автоматически и к новым цепям. Цвет класса используется для линий связи на схеме
(рисунок 1), ширина — для проводников на плате.

<p class="caption tcap">Таблица 4 — Классы цепей</p>

| Класс | Шаблоны имён цепей | Цвет на схеме | Ширина проводника, мм |
|---|---|---|---|
| Power_12V | `Б` (+12 В), `В` (−12 В) | бирюзовый | 0,5 |
| Power_3V3 | `А` (выход DA9) | красный | 0,4 |
| GND | `GND` | синий | 0,5 |
| Digital | `Г`, `Д`, `Е`, `Ж`, `З`, `В2`, `В10`, `В12`, `В13`, `Net-(DD*` | фиолетовый | 0,25 |
| Analog | `Net-(DA*`, `Net-(VD*`, `Net-(VT*`, `Net-(HL*`, `Net-(R*`, `Net-(C*` | охра | 0,3 |
| Default | прочие | — | 0,2 |

Имена цепей в схеме записаны кириллицей («Б», «В», «А», «В2» и т. д.), поэтому шаблоны тоже
набраны кириллицей: латинская «B» и кириллическая «В» для KiCad — разные символы. Безымянные
цепи аналогового тракта KiCad называет по первому выводу (`Net-(DA3-Pad2)`), поэтому для них
использованы шаблоны с подстановкой `*`. По списку цепей (`kicad-cli sch export netlist`)
проверено, что каждая цепь схемы попадает в один из классов: 35 — Analog, 14 — Digital,
2 — Power_12V, 1 — Power_3V3, 1 — GND.

## 8. Библиотека как git-сабмодуль, относительные пути

Библиотека вынесена в отдельный репозиторий `kicad-gost-lib` и подключена к проекту
сабмодулем в папку `lib/kicad-gost-lib`. Так одну библиотеку можно использовать в нескольких
проектах, а каждый проект зафиксирован на конкретной версии библиотеки (коммите).

Как подключался сабмодуль:

```bash
cd pulse-oximeter
git submodule add ../kicad-gost-lib.git lib/kicad-gost-lib
git commit -m "Библиотека kicad-gost-lib подключена сабмодулем"
```

Файл `.gitmodules`:

```
[submodule "lib/kicad-gost-lib"]
    path = lib/kicad-gost-lib
    url = ../kicad-gost-lib.git
```

URL сабмодуля **относительный**: он отсчитывается от адреса основного репозитория. Если оба
репозитория лежат в одном аккаунте GitHub, ссылка сама превращается в
`https://github.com/<логин>/kicad-gost-lib.git` — при переносе или форке ничего менять не нужно.

Пути к библиотеке в проекте тоже относительные — через переменную `${KIPRJMOD}` (папка проекта):

```
(sym_lib_table
  (version 7)
  (lib (name "GOST_UGO")(type "KiCad")
       (uri "${KIPRJMOD}/lib/kicad-gost-lib/symbols/GOST_UGO.kicad_sym")(options "")(descr "УГО по ЕСКД"))
)
```

Рамка подключена так же: `${KIPRJMOD}/lib/kicad-gost-lib/drawing_sheets/GOST_form1.kicad_wks`.
Посадочные места и 3D-модели взяты из штатных библиотек KiCad (`${KICAD10_3DMODEL_DIR}` и т. п.),
абсолютных путей в файлах проекта нет. Обновить библиотеку до последней версии:

```bash
git submodule update --remote lib/kicad-gost-lib
git commit -am "Обновлена библиотека kicad-gost-lib"
```

## 9. Скрипт проверки и выпуска

Скрипты `scripts/build.sh` (Linux, macOS, Git Bash в Windows) и `scripts/build.bat` (Windows)
выполняют одинаковые шаги через консольную утилиту KiCad `kicad-cli` (таблица 6). Скрипт сам
находит `kicad-cli` (в `PATH`, в стандартной папке установки KiCad или по переменной `KICAD_CLI`)
и, если сабмодуль не загружен, выполняет `git submodule update --init`.

<p class="caption tcap">Таблица 6 — Шаги скрипта</p>

| Шаг | Команда `kicad-cli` | Результат |
|---|---|---|
| 1. ERC | `sch erc --severity-all` | `output/reports/erc.rpt` |
| 2. DRC + сверка со схемой | `pcb drc --schematic-parity --severity-all` | `output/reports/drc.rpt` |
| 3. Gerber | `pcb export gerbers` (F/B.Cu, Mask, Paste, Silkscreen, Edge.Cuts) | `output/gerber/*.g*` |
| 3. Сверловка | `pcb export drill --excellon-separate-th --generate-map` | `output/gerber/*.drl`, карты PDF |
| 3. Архив для завода | `zip` / `Compress-Archive` | `output/pulse_oximeter_gerber.zip` |
| 4. BOM | `sch export bom` (группировка по номиналу, корпусу, партномеру) | `output/pulse_oximeter_BOM.csv` |
| 5. PDF схемы | `sch export pdf` (цветная и `--black-and-white`) | `output/pulse_oximeter_schematic*.pdf` |

Запуск:

```bash
./scripts/build.sh                             # Linux / macOS
KICAD_CLI=/путь/к/kicad-cli ./scripts/build.sh
```

```bat
scripts\build.bat                              :: Windows (или двойной щелчок)
```

Скрипт считает в отчётах ERC и DRC отдельно ошибки и предупреждения. Код возврата: **0** — ошибок
нет (предупреждения допустимы); **1** — есть ошибки ERC/DRC или шаг не выполнен (файлы всё равно
выпускаются); **2** — не найден `kicad-cli` или не загружен сабмодуль. Поэтому скрипт подходит и для
автоматической проверки (CI). Пример вывода:

```
=== 1/5 ERC — проверка электрических правил схемы ===
  ошибок: 66, предупреждений: 76  ->  output/reports/erc.rpt
  !! ERC: есть ошибки
=== 2/5 DRC — проверка правил проектирования платы ===
  ошибок: 0, предупреждений: 232  ->  output/reports/drc.rpt
=== 3/5 Gerber и файлы сверловки ===
Plotted to 'output/gerber/pulse_oximeter-F_Cu.gtl'.   … (9 слоёв)
Created file 'output/gerber/pulse_oximeter-PTH.drl'
=== 4/5 BOM — перечень элементов ===
Wrote bill of materials to 'output/pulse_oximeter_BOM.csv'.
```

## 10. Результаты проверки ERC и DRC

<p class="caption tcap">Таблица 7 — Результат последнего прогона скрипта</p>

| Проверка | Ошибок | Предупреждений | Что означает |
|---|---|---|---|
| ERC | 66 | 76 | см. ниже |
| DRC | 0 | 232 | нарушений правил трассировки нет; предупреждения — расхождения платы со схемой и с библиотекой |

**ERC.** Ошибки отражают незавершённые места схемы:

* 46 — «вывод не подключён»: неиспользуемые выводы DD1 (PA0, PA5, PA7, PA8, PA11–PA15, PB1,
  PB3–PB9, PB14, PB15, PC13–PC15, PF0, PF1, PF6, PF7), DD2 (в том числе USBDP/USBDM — разъём USB
  на схеме пока не нарисован) и OUT3/OUT4 у DA8. Неиспользуемые выводы нужно отметить флагом
  «не подключено» (клавиша Q), а для DD2 — добавить разъём USB;
* 7 — «вход не управляется»: те же неподключённые входы DD2;
* 12 — «вывод питания не управляется»: цепи питания приходят с разъёма X1, KiCad требует отметить
  их символом `PWR_FLAG`;
* 1 — висящий провод.

Предупреждения ERC — в основном «символ отличается от библиотеки»: символы схемы обновлены
вручную или созданы в другой версии KiCad. Устраняются командой
*Инструменты → Обновить символы из библиотеки*.

**DRC.** Ошибок правил (зазоры, ширина, отверстия, край платы) нет. Предупреждения:

* 153 — сверка со схемой (`--schematic-parity`): после замены символов на ГОСТ-УГО и
  переобозначения (DA16 → DA9, X2 → X1, FT232RL → DD2) плата ещё не обновлена из схемы.
  Устраняется командой *Инструменты → Обновить печатную плату из схемы* (F8);
* 79 — посадочные места на плате отличаются от текущей версии библиотеки KiCad.

Минимальный зазор «медь — край платы» установлен 0,4 мм. Это обычное технологическое
ограничение изготовителей плат 2-го класса; прежнее значение 0,5 мм давало 2 нарушения у
крепёжного отверстия.

## 12. Публикация на GitHub

Нужны два репозитория в одном аккаунте: `kicad-gost-lib` (библиотека) и `pulse-oximeter`
(проект). На github.com создаются пустые репозитории (*New repository*, без README), затем:

```bash
# 1. библиотека
cd kicad-gost-lib
git remote add origin https://github.com/<логин>/kicad-gost-lib.git
git push -u origin main

# 2. проект
cd ../pulse-oximeter
git remote add origin https://github.com/<логин>/pulse-oximeter.git
git submodule sync            # сабмодуль начинает ссылаться на GitHub
git push -u origin main
```

На странице `pulse-oximeter` папка `lib/kicad-gost-lib` отображается ссылкой на репозиторий
библиотеки с номером коммита. Отчёт `README.pdf` получен из этого файла `README.md`.
